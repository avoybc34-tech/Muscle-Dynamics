1Upload the FULL folder contents

Extract the ZIP. Create a private GitHub repository. Upload the contents of muscle-dynamics-full/, not the ZIP or an enclosing folder.

At repository root you must see render.yaml, package.json, public/, mobile/ and .github/workflows/build.yml. If the hidden .github folder is skipped, create that exact workflow path with GitHub’s Add file → Create new file, then paste the included file. Keep both lockfiles.

2Deploy on Render—not Static Site

Render → New → Blueprint → connect the repository → review both services/disks and prices → Apply.

Leave Root Directory unset. Render installs dependencies, starts a private MariaDB service, applies migrations and runs the web server. No local npm, home-PC database URL or manual SQL import is needed for a fresh deployment.

3Create owner, then add real gym details

Open the public URL of muscle-dynamics-web. Privately copy BOOTSTRAP_TOKEN from that web service’s Environment page. Visit YOUR-WEB-URL/setup.html to create your real owner account.

At /admin.html, enter real contact details, privacy/membership policies, payment instructions, PKR plans/prices and bank/Easypaisa/JazzCash accounts. Registration stays closed until required contacts and policies are ready. Remove the bootstrap token after successful setup.

Member area: /member.html. Health: /api/health. No fabricated members, prices or payment accounts are included. Always verify actual funds before approving a manual payment.

4Build APK and unsigned IPA on GitHub

Repository → Actions → Build APK and unsigned IPA → Run workflow. Choose platform, enter the Render HTTPS website origin (without /api), acknowledge test-build limitations, and run.

Download the artifacts after successful jobs. A blank backend URL can be entered in the app’s Connect screen later. The app uses the same server/accounts as your website.
